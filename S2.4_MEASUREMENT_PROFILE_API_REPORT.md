# S2.4 — Measurement profile API

## Verdict

PASS. Реализован singleton Measurement Profile API поверх существующей таблицы. 139 targeted tests (113 DTO/error/OpenAPI + 26 PostgreSQL integration), 6 health и 10 Item regression tests прошли.

## API implemented

| Method | Path | Semantics |
| --- | --- | --- |
| GET | `/api/profile/measurements` | Текущий профиль либо `200 null`; строку не создаёт. |
| PATCH | `/api/profile/measurements` | Partial upsert единственного профиля, 200 с DTO. |

DTO содержит семь numeric fields, extra_measurements и updated_at. Технический id не возвращается. Decimal сериализуется стандартным Pydantic 2 способом — JSON string; null остаётся null.

## Empty-state semantics

**GET absent profile → 200 null.** Отсутствие строки — нормальное состояние, не 404. Два последовательных GET на пустой БД не создают профиль: row count остаётся 0.

## Update semantics

- Singleton всегда `id=1`. PATCH создаёт строку при отсутствии либо обновляет существующую; повторные PATCH сохраняют row count = 1.
- Numeric omission сохраняет значение; при создании отсутствующие numeric fields становятся NULL. Explicit null очищает поле.
- Numeric values конечные, > 0 и ≤ 9999.99. Bool, zero, negative, NaN/Infinity и значения вне диапазона отклоняются с 422 до DB write.
- Значения округляются до двух знаков через ROUND_HALF_UP, соответствуя положительным NUMERIC(6,2): `39.125 → 39.13`. Значение, округляющееся в 0, отклоняется; `0.005 → 0.01` допустимо. Проверены совпадение response и persistence, а также верхняя граница 9999.99.
- extra_measurements: JSON object; omission сохраняет, при создании default `{}`. Переданный object полностью заменяет текущий; `{}` очищает; null запрещён. Deep merge отсутствует.
- Empty PATCH создаёт пустой singleton при отсутствии. Для существующего профиля — no-op с текущей DTO.
- updated_at использует естественное поведение ORM: изменение сохраняемого значения обновляет timestamp; пустой PATCH и повторное присваивание того же значения не вызывают UPDATE и сохраняют timestamp. Schema не менялась.
- Operations выполняют SELECT/mutate/create/flush, router — commit/rollback. IntegrityError при flush/commit возвращает безопасный `500 profile_write_failed`; подробности остаются в server log. PostgreSQL tests подтверждают rollback создания/изменения после настоящего flush.
