Item ID проверяется как положительный safe integer существующим helper. Invalid ID показывает «Вещь не найдена» без API requests. GET 404 показывает тот же state со ссылкой возврата, без redirect. Route `new` корректно отделён от параметрического details route.

На category screen добавлена ссылка «Добавить вещь» с current category ID; названия вещей в карточках ведут на details. Поведение category navigation и mobile layout S2.6 сохранено.

## API layer

`frontend/src/api/items.ts` расширен typed GET `/api/items/{item_id}`, POST `/api/items` и PATCH `/api/items/{item_id}` через существующий openapi-fetch client. Request/response types берутся из generated contract, ручных DTO нет. GET 404 возвращает `null`, остальные ошибки обрабатываются query/error states.

- `useItemQuery(id)`: key `['item', id]`, reactive ID; invalid ID отключает query.
- `useCreateItemMutation()`: invalidates `['items']` и `['item', created.id]` до navigation на details.
- `useUpdateItemMutation()`: invalidates `['item', updated.id]` и `['items']`, active queries refetched до navigation.
- Совместимый list key S2.6 сохранён: `['items', filters]`.

Global cache abstraction, duplicated server store и `window.location.reload()` отсутствуют. Mutation errors показываются безопасным сообщением; ввод сохраняется для исправления и повторного submit. Pending mutation блокирует повторный submit.

## Create flow

Общая `ItemForm.vue` используется create и edit. Категории flatten из existing categories query, labels содержат глубину; seeded names не hardcoded. Existing category query preselect применяется только к известному ID; invalid/unknown ID оставляет selector пустым. Cancel возвращает в исходную известную категорию либо каталог.

Individual: понятный label, quantity input отсутствует, quantity omitted. Grouped: обязательный integer input, значение 0 и >1 допустимы; empty, negative и decimal блокируются до mutation. Name trim, категория, tracking mode, condition и JSON object проверяются локально.

Condition выбирается по name. Purposes/climates — отдельные наборы native checkboxes с touch targets, допускают несколько или zero selected values. Optional brand/model/color/size/material/notes находятся в вторичном раскрываемом section; пустые create scalar fields omitted.

Extra attributes — отдельный expandable JSON textarea. Invalid JSON и array/string/number/null блокируются локальной понятной ошибкой; пустой create editor отправляет `{}`. Сырой JSON не отправляется backend.

Форма в одну колонку, labels связаны с controls, inputs/textarea используют ширину контейнера, touch targets около 44px, primary submit выделен. Новых UI dependencies нет.

## Edit flow

GET item заполняет текущие scalar values, grouped quantity, relations и extra object. Tracking mode показывается read-only, отсутствует в PATCH; `is_active` также не отправляется. Individual quantity не редактируется и omitted; grouped quantity редактируется, включая 0.

Отправляются поддерживаемые editable fields целиком, без вычисления минимального diff. Очистка scalar fields отправляет `null`, а не omission. Purposes/climates отправляются как replacement arrays; `[]` очищает связи. `{}` очищает extra attributes. Cancel ведёт на details. После успешного PATCH пользователь переходит на актуальные details; списки обновляются при возврате в категорию.

## Details

Показаны name, category name со ссылкой, русское tracking mode, grouped quantity, condition/purpose/climate names, заполненные brand/model/color/size/material/notes, extra JSON object и edit action. Human-readable names используют existing category/reference queries; отдельных endpoints для names не добавлено.

Есть loading/error/404/invalid-ID states. Inactive item отображается со статусом «Не в текущем каталоге» и доступным edit action; remove/restore действий нет. JSON и длинный текст переносятся, metadata доступна без hover/tooltip.
