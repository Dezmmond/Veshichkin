### Migration

- Revision: `0002_reference_data`.
- Previous revision: `0001_initial_schema`, без изменений.
- Head: `0002_reference_data`; chain `<base> → 0001_initial_schema → 0002_reference_data`.
- Seed definitions — простые tuples внутри revision; runtime application code не импортируется.
- Categories: для каждого root PostgreSQL CTE выполняет `INSERT … RETURNING id`, затем child INSERT использует возвращённый ID в том же SQL statement. Generated identity IDs заранее не задаются; Python не читает результат SQL.
- Purposes/conditions/climates добавляются через Alembic `bulk_insert`, без явных ID.
- Offline upgrade: PASS; `/tmp/veshichkin-s1.4/upgrade.sql` содержит schema 0001, reference data 0002, 3 category CTE и INSERT всех справочников.
- Offline downgrade: PASS; `/tmp/veshichkin-s1.4/downgrade.sql` сначала удаляет child categories по точным исходным name/root-parent combinations, затем root categories по name и parent_id IS NULL, затем purposes/conditions/climates по конкретным code. После 0002 следует schema downgrade 0001. Unrestricted full-table DELETE отсутствует.
- Downgrade identification категорий ограничено исходными name/parent combinations, как задано постановкой. Переименованные или перемещённые категории могут остаться при откате только 0002; существующие RESTRICT FK блокируют удаление используемых записей. Отдельный provenance mechanism не добавлялся.
- PostgreSQL smoke: **SKIPPED** — тестовый DSN отсутствует. Development/production БД не использовалась, Docker не запускался.
