# S2.9 — Measurement Profile frontend

## Verdict

PASS. Реализован singleton Measurement Profile frontend: empty → заполнение → view → edit → refetched view. Все 245 frontend tests, typecheck, production build и runtime smoke Variant B прошли.

## Route

`/profile/measurements` — полноценный экран «Мои замеры». Ссылка добавлена в основную навигацию между каталогом и ревизией; active link и переходы проверены. Revision placeholder не изменён.

## API layer

`frontend/src/api/profile.ts` использует existing `apiClient`, generated contract и TanStack Vue Query:

- GET `/api/profile/measurements`, `useMeasurementProfileQuery()`, key `['measurement-profile']`.
- PATCH того же endpoint, `useUpdateMeasurementProfileMutation()`; success invalidates тот же key и ожидает active refetch перед view mode.
- GET `null` принимается как нормальный результат; HTTP/network errors отображаются безопасно.

Ручных backend DTO interfaces, polling, global server-state копии и cache abstraction нет.

## Empty state

`200 null` → «Замеры пока не сохранены.» и «Заполнить замеры». Mutation автоматически не запускается. Открытие формы и Cancel остаются на том же route; Cancel возвращает исходный empty/view state без PATCH.

## Form semantics

Первое заполнение и edit используют одну `MeasurementProfileForm.vue` с семью полями: height_cm, weight_kg, chest_cm, waist_cm, hips_cm, inseam_cm, foot_length_cm. Русские labels и единицы см/кг видимы; форма в одну колонку, inputs с `inputmode="decimal"`, controls около 44px. JSON section вторичен, Cancel визуально отделён от primary Save.

Numeric form state и PATCH values — строки, без float/int parsing или округления. Validation допускает значения > 0 и <= 9999.99 с максимум двумя decimal places; 0, negatives, invalid text, NaN, Infinity, exponent notation и превышение precision/range блокируются локально. Decimal comma преобразуется в точку, `.01` в `0.01`, leading zeros нормализуются; fractional digits сохраняются, включая `0.01` и `182.00`.

Пустые numeric fields отправляются как `null`; edit clearing отличим от omission. Разрешено заполнить любой subset, например только стопу; при submit передаются все семь поддерживаемых numeric fields с корректными null semantics. Backend создаёт singleton через PATCH.

`extra_measurements` — controlled JSON-object textarea в expandable section «Дополнительные замеры». Existing object отображается форматированным JSON, пустой object — `{}`. Invalid JSON и array/string/number/null блокируются до mutation; object отправляется целиком как replacement, `{}` очищает custom measurements. Arbitrary keys не интерпретируются как domain schema.

Во время mutation повторный Save и Cancel блокируются, включая ожидание refetch. Ошибка PATCH показывает «Не удалось сохранить замеры.» и сохраняет введённые values для retry. Ошибка GET показывает «Не удалось загрузить замеры.»; raw backend errors не выводятся.

## View mode

Показываются только non-null numeric values с русскими labels и units; response decimal strings сохраняются в отображении. Непустой extra object показывается форматированным JSON с переносом строк.

Existing singleton с all numeric null и `{}` показывает «Замеры пока не заполнены.» и «Редактировать»; он отличим от отсутствующего profile. Extra-only profile отображается без ошибочного empty-content сообщения. После PATCH/refetch пользователь видит актуальные saved values без reload; повторное открытие edit использует обновлённые значения.
