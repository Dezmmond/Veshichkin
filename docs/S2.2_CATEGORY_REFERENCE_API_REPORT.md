## API implemented

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/categories` | Полное дерево; один SELECT, построение в Python. |
| POST | `/api/categories` | Создание root/child; 201 с обычной category DTO. |
| PATCH | `/api/categories/{category_id}` | Частичные name, parent_id, sort_order; 200. |
| DELETE | `/api/categories/{category_id}` | Удаление только неиспользуемой категории; 204 без тела. |
| GET | `/api/reference/purposes` | Чтение purposes. |
| GET | `/api/reference/conditions` | Чтение conditions. |
| GET | `/api/reference/climates` | Чтение climates. |

JSON сохраняет snake_case. Обычная DTO: `id`, `name`, `parent_id`, `sort_order`; tree DTO дополнительно содержит `children`.

## Category invariants

- Имя trim и непустое; sort_order ≥ 0. Одинаковые имена разрешены.
- Отсутствующий parent → `404 category_parent_not_found`; отсутствующая категория → `404 category_not_found`.
- Маленькая pure-функция `validate_parent` проходит parent chain по IDs; self-parent, прямой и глубокий циклы → `409 category_cycle`. Seeded names/IDs в application logic отсутствуют.
- PATCH различает отсутствие поля и явный `parent_id: null` (перенос в root). Явный null для name/sort_order отклоняется с 422.
- Изменение parent сериализуется PostgreSQL `LOCK TABLE categories IN SHARE ROW EXCLUSIVE MODE` до чтения hierarchy; блокировка действует до завершения транзакции и предотвращает взаимные циклические переносы.
- Delete проверяет child categories, все items (включая inactive) и revision_category_results. Зависимости → `409 category_in_use`; каскадного удаления нет.
- DB RESTRICT сохранён. IntegrityError при flush/commit DELETE вызывает rollback и безопасный `409 category_in_use`, без SQL/constraint details.
- Одна mutation — одна DB transaction. Commit/rollback находятся в router; operations делают SELECT/flush без commit. Используется существующий ApplicationError envelope.

## Reference API

- `/api/reference/purposes`: `id`, `code`, `name`, `sort_order`; порядок `sort_order, name, id`.
- `/api/reference/conditions`: `id`, `code`, `name`, `rank`, `description`; порядок `rank, name, id`.
- `/api/reference/climates`: `id`, `code`, `name`, `sort_order`; порядок `sort_order, name, id`.

Сортировка выполняется в SQL. Write endpoints отсутствуют.
