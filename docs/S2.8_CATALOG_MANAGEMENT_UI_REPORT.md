# S2.8 — Catalog management UI

## Verdict

PASS. Реализованы structured filters, non-destructive item removal с confirmation и минимальный Category CRUD frontend. Все 196 frontend tests, typecheck, production build и runtime smoke Variant B прошли.

## Filters

| Filter | UI | Backend parameter | Status |
| --- | --- | --- | --- |
| Category | Optional select с flattened tree на `/catalog` | `category_id`, exact category | PASS |
| Condition | Single-select, «Все состояния» | `condition_id` | PASS |
| Purpose | Single-select, «Все назначения» | `purpose_id` | PASS |
| Climate | Single-select, «Любой климат» | `climate_id` | PASS |
| Tracking mode | Все / Индивидуальные / Группы | `tracking_mode` | PASS |

`/catalog` сохраняет root navigation и добавляет «Все вещи». Общие `CatalogFilters.vue` и `CatalogItemList.vue` используются root/category screens. Filters непосредственно передаются в `useItemsQuery()`; комбинации используют существующие keys `['items', filters]`. Локальной фильтрации массива items нет. Labels категорий и references берутся из API, seeded values не hardcoded.

На category page selector категории отсутствует; `category_id` всегда равен текущему route ID, включая reset и переход в другую категорию. Reset убирает дополнительные filters, на root — все filters. Пустые результаты с активными пользовательскими filters показывают «По выбранным фильтрам ничего не найдено.» и доступный reset; фиксированная категория сама по себе не считается дополнительным фильтром. Unfiltered empty states сохранены.

## Item removal

Active details содержит «Убрать из каталога». Inline confirmation показывает название вещи и «Запись и её данные сохранятся.». Отмена не отправляет DELETE; pending блокирует повторный submit и cancel. `window.confirm()` не используется.

Typed DELETE `/api/items/{item_id}` использует существующий generated client. После success invalidated списки и details, экран остаётся на details и показывает «Не в текущем каталоге». Remove action исчезает, edit остаётся. Restore/hard-delete UI отсутствуют; обычные списки исключают inactive вещи по backend semantics.

При DELETE error details остаются видимыми, выводится «Не удалось убрать вещь из каталога.», без raw JSON/SQL/stack.

## Category CRUD

| Operation | Route/UI | Status |
| --- | --- | --- |
| Create root | `/catalog` → `/catalog/categories/new`, parent по умолчанию null | PASS |
| Create child | Category → `/catalog/categories/new?parent_id=<id>` | PASS |
| Rename | `/catalog/categories/:categoryId/edit`, name trim | PASS |
| Reparent | Parent selector на edit | PASS |
| Parent null | «Без родительской категории», explicit `parent_id: null` | PASS |
| sort_order | Integer input >= 0 | PASS |
| Delete | Отдельный action на edit с confirmation | PASS |

Create/edit используют общую `CategoryForm.vue`: name, parent_id, sort_order. Name обязателен, одинаковые имена не блокируются; пустой/negative/decimal sort order запрещён. Parent options исключают текущую категорию и descendants. Неизвестный parent preselect безопасно означает root. Edit использует существующее дерево без нового GET category endpoint; invalid ID не вызывает API, unknown ID показывает not found после загрузки дерева.

Typed POST/PATCH/DELETE используют generated DTO aliases. После create/update navigation ведёт в категорию с refetched tree, поэтому breadcrumb и navigation отражают актуальное имя/parent/backend order. Delete confirmation поясняет ограничения на children/items/revisions. После 204 categories refetched и выполняется переход в `/catalog`. Каскадные изменения, перенос вещей и удаление children не выполняются.

Обработаны `category_not_found`, `category_parent_not_found`, `category_cycle`, `category_in_use`; остальные HTTP/network errors отображаются безопасными operation messages. Backend остаётся окончательной защитой от cycles и удаления используемой категории.

Формы/filters в одну колонку, controls и actions имеют touch targets около 44px, delete отделён от Save. Global redesign и новые UI dependencies отсутствуют.

## Query invalidation

- Item remove: `['items']` и `['item', id]`; active detail refetched, inactive lists refetched при возврате.
- Category create/update/delete: `['categories']`; все category/reference labels, parent options и breadcrumb используют это дерево и обновляются через invalidate/refetch.
- Существующая invalidation item create/update сохранена. Optimistic/manual cache layer и глобальный state store не добавлены.
