## API changes

| Method | Path | Change |
| --- | --- | --- |
| GET | `/api/items` | Пять optional filters; response содержит purpose_ids/climate_ids. Только active, порядок name ASC/id ASC. |
| GET | `/api/items/{item_id}` | Relations в response; inactive запись остаётся адресуемой. |

## Relations semantics

- Response содержит только IDs, всегда массивы, ID ASC; отсутствующие relations → `[]`. Reference names/codes не дублируются.
- Create: omission/пустой массив → без relations. Проверяются все IDs перед записью.
- PATCH: omission сохраняет relation, массив полностью заменяет её, `[]` очищает. Purpose/climate sets независимы.
- Payload IDs — строго положительные integers; null, duplicates, bool/float/string IDs отклоняются с 422.
- Missing purpose/climate → `404 purpose_not_found` / `404 climate_not_found`, включая IDs за пределами SMALLINT.
- Scalar + purpose replacement + climate replacement — одна transaction. Operations query/mutate/flush без commit; commit/rollback остаются в router. Проверены rollback при missing references и при IntegrityError после реального flush scalar/association изменений.
- List/get используют пакетную загрузку обеих association tables. SQL counter подтверждает 3 SELECT для непустого list как с 1, так и с 8 items; get также 3 SELECT. N+1 отсутствует.

## Filtering

| Filter | Semantics |
| --- | --- |
| `category_id` | Точная категория; descendants не включаются. |
| `condition_id` | Точное совпадение текущего condition. |
| `purpose_id` | Наличие association через EXISTS. |
| `climate_id` | Наличие association через EXISTS. |
| `tracking_mode` | Только individual/grouped; другие значения → 422. |

Filters соединяются через AND, всегда действует `is_active=true`. Quantity, включая grouped 0, не влияет на фильтрацию. EXISTS не размножает Item rows; Python deduplication отсутствует. Порядок `name ASC, id ASC` сохраняется.

Неизвестные положительные IDs → `200 []` без existence validation; IDs вне диапазонов существующих DB types также дают пустой результат. Malformed/non-positive IDs → 422. Include-inactive filter отсутствует.

## Removal

DELETE = `is_active=false`; hard delete отсутствует. Identity, category, condition, quantity/tracking mode, все optional scalar fields, JSONB, обе relations и **created_at/updated_at** сохраняются. UPDATE явно сохраняет updated_at, подавляя существующий ORM onupdate default.

Повторный DELETE идемпотентен: 204 без тела, данные сохраняются. List исключает запись, GET по ID возвращает inactive с relations. Полная сохранность подтверждена GET и новой Session после каждого из двух DELETE. Missing ID → `404 item_not_found`. Restore endpoint отсутствует.
