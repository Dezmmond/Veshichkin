# S2.3a — Catalog Item core CRUD

## Verdict

PASS. Реализован backend Item API; 94 targeted Item tests (52 DTO/API/error/contract + 42 PostgreSQL integration), 6 health и 24 Category/Reference regression tests прошли.

## API implemented

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/items` | Только active items; сортировка `name ASC, id ASC`, без pagination. |
| GET | `/api/items/{item_id}` | Получение active/inactive item; отсутствующий ID → `404 item_not_found`. |
| POST | `/api/items` | Создание item, `201`, всегда `is_active=true`. |
| PATCH | `/api/items/{item_id}` | Частичное обновление, `200`; пустой объект — безопасный no-op. |

DTO содержит все заданные поля без category/condition names и purpose/climate relations. Missing references → `404 category_not_found` / `404 condition_not_found`; проверки не зависят от seeded names/IDs. Непредставимые в типе DB IDs также получают соответствующий 404 до SELECT.

## Semantics

- `tracking_mode`: только `individual` / `grouped`, задаётся при создании и отсутствует в PATCH DTO. Неизменяемые и неподдерживаемые поля отклоняются с 422.
- Individual: отсутствующая create quantity становится `1`; явная `1` допустима, другие значения → 422, включая PATCH.
- Grouped: create quantity обязательна, integer ≥ 0; PATCH позволяет изменить quantity. Boolean, float, string, null и отрицательные значения отклоняются. Верхняя граница `2147483647` соответствует существующему PostgreSQL INTEGER и предотвращает overflow до flush.
- Name trim, пустое имя → 422; одинаковые имена допустимы.
- PATCH omission сохраняет значения; null очищает brand/model/color/size/material/notes. Все эти строки trim, пустые строки становятся NULL. Null для name/category_id/condition_id/quantity запрещён.
- `extra_attributes`: JSON object; create omission → `{}`, PATCH omission сохраняет объект, переданный объект полностью заменяет его, null отклоняется. Deep merge отсутствует.
- SELECT/mutate/flush находятся в operations; commit/rollback — в router. Unexpected IntegrityError при flush/commit вызывает rollback и безопасный `500 item_write_failed`; SQL/constraint details записываются только server-side.
- Response допускает `condition_id=null` для ранее существующих строк: текущая persistence schema допускает NULL. Create требует condition_id, PATCH запрещает его очищение; схема не менялась.
